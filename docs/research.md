# Phase 1 research

Every claim below comes from reading the referenced repository or from a build
attempt on this machine. Hardware results are marked as such and only when they
were observed.

## 1. Java runtime: what it is and what it cannot do

Sources: `ps5-java25-homebrew`, `ProsperoCraft`, released probe packages.

- The runtime is **OpenJDK 25** (FreeBSD fork, `jdk-25.0.4+7-freebsd-1`) built for
  `x86_64-sie-ps5` with the payload SDK. Only the macOS build host is supported
  upstream; the build workspace needs roughly 1 GiB of OpenJDK source plus a
  configured HotSpot tree.
- In consumer titles the runtime is **linked into the title**, not loaded from
  disk. `ProsperoCraft/server/native/bootstrap.cpp` runs the constructor array
  emitted by the merges (`__jvm_init_array_start`) and then calls
  `JNI_CreateJavaVM` directly.
- `ps5-java25-homebrew/Development/tools/java25_builtin_runtime.py` documents the
  mechanism in its own docstring: *"This is an embedded-library adapter, not a
  loader for arbitrary ELF modules."* The SDK's `__dlopen`/`__dlsym` callbacks are
  bound to a generated table of 932 statically linked core-library symbols.
  **Arbitrary ELF modules and external JNI libraries are unsupported.**
- The released probe packages do contain plain shared objects
  (`assets/java25/lib/server/libjvm.so`, `libjava.so`, `libzip.so`, `libnet.so`,
  `libnio.so`, `libjimage.so`) plus a `lib/modules` image. Inspected with
  `readelf`: `libjvm.so` exports `JNI_CreateJavaVM` and needs
  `libkernel_web.sprx`, `libSceLibcInternal.sprx`, `libSceNet.sprx`; the other
  libraries are mutually dependent through `libjvm.so`.
- Consequence: loading those `.so` files at runtime is **not** a supported path
  today. PS5Craft does not pretend otherwise. `platform/ps5/runtime_ps5.cpp`
  encodes the exact requirements, and the console surfaces a precise error when
  they are absent.

Verified JVM options (from the ProsperoCraft server bootstrap, all exercised on
console by that project): `-Xmixed`, `-XX:TieredStopAtLevel=1`,
`-XX:CICompilerCount=1`, `-XX:CompileThresholdScaling=4.0`,
`-XX:ReservedCodeCacheSize=16m`, `-XX:CompressedClassSpaceSize=32m`,
`-XX:MetaspaceSize=128m`, `-Xshare:off`, `-XX:+UseSerialGC`,
`-XX:NewRatio=15`, `-XX:ActiveProcessorCount=2`, `-XX:UseAVX=0`,
`-XX:UseSSE=2`, `-XX:+UseCompactObjectHeaders`, `-Xss512k`.

Heap: 224 MiB for Fabric, 384 MiB for Paper in the tested builds. Larger heaps
were not established.

## 2. Minecraft server execution

Source: `ProsperoCraft/server/`.

- Verified on console: **Vanilla 26.3**, **Fabric 26.3** (loader 0.19.5) and
  **Paper 26.3 build 207**. Paper and Fabric have playtest reports; two-hour
  endurance is explicitly pending upstream.
- The server JAR is the unmodified upstream artifact. `execution.json` records
  `active_game_transformations: []` and `replacement_game_classes: []`.
- Working directory, `java.home`, classpath, temp dir and log config are all set
  through `-D`. `-Dlog4j2.disableJmx=true` avoids an unported JMX path.
- Unsupported or unproven: Spigot, Purpur, Pufferfish, Forge, NeoForge, Quilt.
  These are not advertised by PS5Craft until tested.
- One JVM per process is a JNI rule. Parallel instances need separate processes;
  homebrew titles cannot `fork`/`execve` arbitrary ELFs (`docs/process-launch.md`
  in PlayKit documents the `rfork_thread` + `ptrace` replacement used by
  `elfldr`). PS5Craft therefore supports one running server per title process and
  states this in the UI.

## 3. Web server

Source: `websrv` (`ps5-payload-dev`).

- Single-threaded-select loop around **libmicrohttpd**; routes are registered with
  `MHD_start_daemon` and callbacks in `src/websrv.c`.
- Existing routes: `/`, `/index.html`, `/elfldr`, `/fs/` (HTML and `?fmt=json`),
  `/mdns`, `/smb`. Static assets are embedded as C arrays generated by
  `gen-asset-module.py`.
- File serving goes through `src/fs.c`, which has no sandbox: any path the process
  can open is reachable. PS5Craft must not expose that route.
- **No WebSocket route.** MHD here does not handle upgrades. The dashboard polls.
- Build: `Makefile.ps5` links `libmicrohttpd.a` built by `libmicrohttpd.sh` with
  PacBrew. That dependency chain is not present on this machine.

## 4. Vulkan and the native UI

Sources: `PS5_VulkanTemplate`, `PS5_VKHomebrewUI`, `PS5_Vulkan`.

- The template is the reference for a Vulkan title: base class, pad input, klog,
  test runs, `tools/new-title.py`, `tools/link-title.sh`.
- It requires **two things that are not in this environment**:
  1. `PS5_PayloadSDK` fork revision `611893f` (adds `libps5platform.a` and
     `include/ps5platform`). The stock payload SDK here has neither.
  2. A RADV archive built from `PS5_Mesa` (`tools/build-radv.sh`), which needs a
     Mesa checkout and a meson/ninja build. `PS5_Vulkan` publishes **no release
     assets**; the archive must be built.
- `PS5_VKHomebrewUI` provides the widget kit, themes, focus model and 99
  components over a backend-neutral `gfx::Renderer`. Adopting it means adopting
  GPL-3.0 and the RADV link recipe.
- Therefore the first console builds of PS5Craft render through the title's
  own presentation path, and the UI code is written against a small screen
  abstraction so the Vulkan backend can be dropped in without touching feature
  code.

## 5. Filesystem, archives, metrics

- `BFpilot` (`src/fs.c`, `fs_at.c`) uses `openat`-relative traversal and explicit
  path validation; useful as a model for the sandbox rather than as code.
- `Prospero Explorer` is C#/SDL and cannot be linked here.
- `ps5-exporter` reads CPU load, temperatures, fan and memory through exported
  SDK calls (`cpuload.c`, `sensors.c`, `metrics.c`) and exposes them over HTTP.
  PS5Craft uses the same read-only sources and labels system-wide values as such.
- `PS5_DevTools` collects klog and crash records; useful for diagnostics, not for
  Minecraft console capture. Minecraft stdout is captured by PS5Craft itself.
- Filesystem limits recorded by the Java port: no `chown` (EPERM), no xattr
  (ENOTSUP), `statvfs` capacity unavailable from NIO, no `fstatvfs`. Backup and
  storage code must tolerate missing capacity figures instead of inventing them.

## 6. What this means for the build

| Area | Decision |
| --- | --- |
| Runtime | Consume `ps5-java25-homebrew`; never vendor or fake it |
| Server flavours | Vanilla, Fabric, Paper only after console test |
| Instances | One running JVM per process; documented |
| HTTP | libmicrohttpd, keep-alive, polling; no WebSocket |
| Files | Sandboxed to the PS5Craft data root; no `/fs/` route |
| Metrics | System-wide only; no per-server memory claims |
| Graphics | Screen abstraction now; Vulkan backend when RADV is buildable |
